# Life Lab v2 - 全生命体 AI 融合系统 规范

## 问题与目标
用户希望将 Life Lab 原有的四种生命体模拟升级为**统一架构下的融合系统**:
- 给自主感知 Agent 加上**神经进化决策大脑**(不再用规则 think(),换成可突变/可遗传的小神经网络);
- 给生态系统加上**基因遗传**(可观测的基因型→表型映射、交叉+突变);
- 给对话宠物接入**真实 LLM**(保留离线规则降级);
- 融入"量子学""小龙虾""爱马仕视觉"作为隐喻化模块;
- 增加**管理者宠物(Manager Pet)**: 一个能观察、调度、学习所有子系统的中央智能体;
- 管理者宠物具备**浏览器学习所有知识**的能力: 用浏览器自动化抓取网页 → 本地 RAG 知识库。

### 非目标
- 不接入真正的量子计算机(QPU)、不引入 qiskit/cirq 等量子库;
- 不接入实际的 "Hermes 视觉模型" 或 "小龙虾" 商业/开源模型(因为不存在);它们以**隐喻化**形式实现(见"概念落地映射"节);
- 不做跨语言混合工程(统一 Python,避免不必要的复杂度);
- 不训练任何真实 CV 大模型(屏幕感知 = 结构化世界状态采样,不是像素 CNN);
- 不保证永远在线的浏览器学习爬取(单次/手动触发式,遵守 robots 基本礼节)。

## 概念落地映射(关键假设)

| 用户语 | 真实实现 | 解释 |
|--------|---------|------|
| 量子学 | **量子启发决策 + 量子隧穿突变** | 决策阶段用概率分布采样模拟"叠加→坍缩";进化阶段用极低概率的"隧穿式"大跳变(跨越局部最优山谷) |
| 小龙虾 | **小龙虾物种 + 触须感知器** | 在生态/Agent 中新增一种生物,具"短距密集触须(8方向距离传感器)+ 冲刺-滑翔运动模式"的物种特征 |
| 爱马仕视觉 | **高品质视觉皮层模块(Vision Cortex)** | Manager Pet 的结构化感知:把模拟世界按网格采样成"物种分布矩阵 / 能量热力图 / 注意力热点",作为 Manager 的视觉输入,而不是裸规则 |
| 管理者宠物 | **统一管理面板 + 中央 LLM Agent** | 新的 manager 模式:可视化所有子系统指标,LLM 可读取系统状态、下发指令(如"在生态里投放 10 株植物""给宠物讲个笑话") |
| 浏览器学习知识 | **Browser Agent + 本地 RAG 知识库** | 用 browser_use 访问用户指定 URL → 抽取正文 → 切片 → 关键词 TF-IDF 索引 → 对话时作为"我最近读了 X 所以知道 Y"的增强上下文 |

## 用户与角色
- **终端用户 (Human)**: 打开程序,选择模式、和 Manager 对话、触发浏览器学习任务;
- **Manager Pet**: 中央智能体,可对话、可观察/调度子系统、可学习新知识;
- **子生命体**: 自主 Agent、小龙虾、食草动物、捕食者、Boids 鸟、对话宠物——它们都是被观察/管理对象。

## 功能需求 (FR)

### FR-1: 神经进化 Agent(替换原 life_agent)
- 每个 Agent 有一个**紧凑的 MLP 神经网络**(NumPy 实现,无 torch 依赖)作为决策脑:
  - 输入:饥饿、能量、情绪值、最近食物方向(角度+距离)、最近威胁(可选)共 6~8 维;
  - 隐藏层 1 层(12~16 个神经元,tanh);
  - 输出:动作概率分布(4 动作:觅食移动/进食/休息/探索)用 softmax;
  - **量子启发决策**:从 softmax 分布按概率采样(而不是 argmax),模拟叠加态坍缩。
- 权重数组本身就是**可遗传的基因型**;
- 提供 `mutate()`(含极低概率"隧穿"大步长突变,即量子学) 和 `crossover(partner)` 算子。

### FR-2: 生态系统基因遗传
- 每个动物(食草/捕食/小龙虾)携带 **Gene 结构**:
  - 速度偏好、视觉半径、攻击性、繁殖阈值、代谢速率,共 5 个浮点数 [0,1];
  - 另外携带一个"外观码"用于颜色可视化(3 维,RGB 比例);
  - 基因型→表型:线性映射成真实参数(如视觉半径 = 50 + gene[1] * 200)。
- **繁殖**:两亲交叉(每段 50% 随机)+ 每个基因位 5% 概率高斯突变 + 0.1% 概率"量子隧穿"(直接重采样到 [0,1] 任意值)。
- 每个生物体 HUD 显示其基因型摘要。

### FR-3: 对话宠物接入真实 LLM
- 新增 `llm_client.py` 模块:
  - 配置契约 `LLMConfig`: base_url、api_key、model 名,从 `llm_config.json` 读取;
  - 实现 OpenAI 兼容 API 客户端(单轮 + 上下文);
  - **必须带离线降级**:当配置不存在/网络失败时,自动回退到现有规则引擎(原 mode_pet 的 respond)。
- 对话宠物的 `respond()` 优先走 LLM:prompt 中注入 情绪/饥饿/好感度/记忆 → LLM 生成回复 → 再根据关键词(例如 LLM 提到"饿了")更新内部状态。

### FR-4: 小龙虾物种
- 在生态系统里新增第三种物种 **Crayfish(小龙虾)**:
  - 视觉退化(短距),但有 **8 方向触须感知器**(每 45° 一个方向,读出最近障碍/食物距离);
  - 运动模式为 **冲刺-滑翔**:加速 3 帧 → 无动力滑行 5 帧,节省能量;
  - 食性:杂食,优先吃植物,食物紧缺时攻击幼体食草动物。

### FR-5: 爱马仕视觉皮层(Manager 的世界感知)
- `vision_cortex.py` 模块:
  - 输入:世界状态(所有生物/物体位置列表 + 网格大小 N×N);
  - 输出 3 通道"视觉图":
    1. 物种密度热力图(每种物种一通道,N×N);
    2. 能量热力图(每个网格能量总和);
    3. 注意力热点(与 Manager 自身位置相关的显著性);
  - 向 LLM 汇报时,把视觉图压缩为文字摘要("生态 3:30 位置植物密集,右下角捕食者聚集")。

### FR-6: Manager Pet 统一管理面板
- 新增 `mode_manager.py`(模式 5,加入主菜单):
  - 左侧:四个子系统的实时指标面板(Agent 能量分布、生态种群数、Boids 数、宠物情绪/好感度);
  - 右侧:与 Manager 对话(走 LLM/规则,FR-3 同一套客户端);
  - Manager 可下发指令: 发送特殊意图 → 程序执行具体操作(示例:
    - "在生态系统投放 20 株植物" → 直接调用 `env.spawn_food(20)`;
    - "让 Agent 重生" → 新建 Agent;
    - "告诉对话宠物你好" → 向宠物对话流插入消息)。
- Manager 状态持久化到 `manager_state.json`。

### FR-7: 浏览器学习知识(RAG)
- `browser_study.py` 模块:
  - 函数 `study(urls: list[str]) -> str`:
    1. 用 browser_use 工具访问 URL,等待加载;
    2. `browser_evaluate` 抽取正文 innerText;
    3. 按段落切片,每片保留关键词(TF-IDF top 10);
    4. 存入本地 `knowledge.jsonl`(追加,持久化);
    5. 返回"学习了 N 片,共 M 词"摘要。
  - 函数 `retrieve(query: str, topk=3) -> list[str]`:
    - 对 query 分词,和知识切片做 Jaccard 相似度;
    - 返回最相关的 topk 片文本。
- Manager 对话中,**LLM prompt 前缀注入 retrieve() 返回的相关知识切片**,实现"学过的内容会提到"。
- Manager 面板新增"学习网页"按钮(输入 URL,回车 → 调用 study)。

### FR-8: 生命周期 + 量子隧穿总览
- 在所有进化/突变点,隧穿概率固定 0.1%(基因突变) + 1%(决策层分布采样);
- 每 500 tick 控制台打印进化统计(隧穿触发次数、当前最强基因特征)。

## 非功能需求 (NFR)
- **NFR-1 无 torch 依赖**:神经网络仅用标准库 + NumPy;
- **NFR-2 单进程可运行**:所有模式仍可在一个 pygame 进程内切换;
- **NFR-3 LLM 零配置可用**:无 API key 时自动离线降级,不报错;
- **NFR-4 浏览器学习可独立**:用户不在 Manager 面板里也能手动调用 `browser_study.py` 脚本;
- **NFR-5 中文 UI**:全部 HUD、菜单、状态用中文。

## 约束 / 依赖
- Python 3.12 + pygame 2.6.1(已安装);
- NumPy(需要 pip 安装);
- `requests`(LLM 客户端 HTTP 调用);
- 真实 LLM 需要用户提供 base_url + api_key(可填本地 Ollama);
- 浏览器学习依赖 Trae 内置 browser_use 工具(无法脱离 Trae 环境时,提供"无浏览器降级": 让用户粘贴文本到输入框,直接写入知识库)。

## 开放问题
1. **LLM 端点**: 用户是否已有 OpenAI 兼容端点(如 OpenAI 官方、DeepSeek、Ollama、自建 Gateway)? 如果没有,默认走纯离线规则降级即可。
2. **浏览器学习 URL 范围**: 目前不限定,用户手动输入 URL。是否要限定白名单(比如只学维基百科、知乎)?
3. **Manager 自动调度强度**: Manager 的"下发指令"目前是**用户对话驱动**(用户说→Manager LLM 解析意图→执行)。是否要额外加 Manager 的自主周期性调度(例如每 300 tick 自动调一次环境参数)? 默认不加,需要再加。

## 验收标准 (Acceptance Criteria)

| ID | 类型 | 内容 |
|----|------|------|
| AC-1 | rule | 程序启动进入主菜单,能看到 5 个模式(新增 5-Manager)且 1-5 均可进入不崩溃 |
| AC-2 | rule | Agent 模式里:Agent 不死亡情况下,5 秒内可见其动作分布从"探索"转向"觅食"的切换 |
| AC-3 | rule | Agent 模式里:按 E(进化)键触发 1 次繁殖,能看到新生 Agent 继承了父本部分权重(控制台打印"继承 + 突变 位:N") |
| AC-4 | rule | 生态系统里:有小龙虾物种(外观可区分,有触须 HUD 小标记);种群数每 5 分钟至少变化 1 次(非恒定) |
| AC-5 | rule | 在 `llm_config.json` 填正确 API 的前提下,宠物模式回复中会引用情绪/饥饿/好感度关键词(例如"我有点饿了");未填配置时返回规则回复不报错 |
| AC-6 | rubric | 视觉皮层质量:3 通道图输出能区分"密集区"和"稀疏区",维度一致性 N×N (0-5 分,≥3 通过) |
| AC-7 | rule | Manager 面板:说"在生态系统投放 5 株植物"后,`生态模式`内进入可观察到植物数净增 ≥3 |
| AC-8 | rule | 浏览器学习:输入一条公开 URL(如 python.org)后,`knowledge.jsonl` 行数增加且 retrieve 能返回相关片段(包含页面主体关键词) |
| AC-9 | rule | 关闭程序再重开,Manager 的 `manager_state.json` 中字段(好感度、记忆)得以恢复 |
| AC-10 | rule | 控制台每 500 tick 打印一次"隧穿统计"(累计触发次数) |
